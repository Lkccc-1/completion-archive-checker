# 竣工资料完整性检查器

> **公开版本说明**
>
> 这是一个**确定性规则 + 信息检索**系统：分类号定位、IDF 关键词覆盖、字符 3-gram 匹配，
> 正文走 PyMuPDF / 离线 OCR，印章走 OpenCV 传统图像处理。**不含任何大模型调用**——
> 这是为政企场景做的取舍（可解释、可离线、结果可复现），不是能力缺失。
>
> 为保护客户资料，仓库不包含：公司内部《归档范围及保管期限表》docx、任何真实工程扫描件、
> 含真实文件名的标注 CSV。因此部分用例会 skip，`评测/` 下的脚本需要自备数据才能复跑。
> 可用性见下方「已知限制」。


对着《电网建设项目、设备仪器类分类、归档范围及保管期限表》这类归档清单，扫描本地竣工资料目录，
自动判断每条检查点是否已有对应文件，输出**可直接下发的 Excel 整改单**。

两路证据：**文件名/路径为主证据**（快、零成本），**PDF 正文为补充证据**（慢但准）。
正文只在需要时读——先抽文字层，扫描件才走本地 OCR，读到能确认对应检查点就停止翻页。

## 功能

- **检查标准**：上传 `.docx` / `.doc` / `.yaml` / `.yml`（公开仓库不含内置模版）；读取“归档内容—主要项目文件—立卷”
  作为检查点，自动拆条、识别序号、识别“其他/备查”类可选项。
  也支持**文件清单**格式的 docx（`序号 | 文件名 | 立卷`，案卷标题行合并单元格）：
  每一份实际文件是一条检查点，核对的是“清单与目录是否一致”，不是归档范围是否齐全。
- **文件扫描**：选择本机资料目录，递归读取文件名、相对路径、分类编码；跳过 Word 锁文件、
  隐藏目录/文件、临时目录和不支持的扩展名；目录只读，不改动任何原始资料。
  同一目录里若还有另一套编码（8x 基本建设 / 9x 设备仪器），扫描后会明确提示文件数并提供
  一键切换——一次只查一套，另一套不会悄悄丢掉。
- **检查引擎**：按“责任单位”（建设/设计/监理/施工，对应“立卷”列）和项目类型过滤检查点，
  再用文件名匹配；结果分为 **已匹配 / 疑似 / 缺失 / 不适用** 四档。
- **正文核验**：对“疑似”项的候选 PDF 读正文（文字层优先，扫描件走离线 OCR），
  正文命中清单的关键词与文书类型时升级为“已匹配”；正文对不上时只提示复核，不降级。
- **印章识别**：对报审表、验收记录、签证、合格证、竣工图等通常需要盖章的文种，
  在证据文件里检测红色印章，给出“有 / 未检出 / 不可判（黑白扫描）”三档结论。
- **人工纠正**：在表格里逐条改判（确认缺失 / 已提供 / 不适用 / 暂不处理），纠正结果按项目落盘，
  关闭页面后再打开仍然保留；撤销纠正会恢复到自动判定结果。
- **导出 Excel**：封面、整改单、疑似清单、已匹配、印章核查、未归类文件、统计、说明共 8 个工作表，
  带表头样式、状态配色、冻结窗格、筛选和打印设置。
- **按内容批量改名**（单独一页 `pages/文件批量改名.py`）：选文件夹 → 读 PDF / Word / 图片的正文 →
  取文件自带的标题生成 ≤40 字的名字 → 表格里预览、可手改 → 确认后才改本地文件名，
  带日志和一键撤销。

## 快速开始

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt
streamlit run app.py
```

**Windows 用户也可以直接双击项目根目录的 `start.bat`**：它会切到项目目录、启动 Streamlit
并自动打开浏览器；启动失败时窗口会停住显示错误，不会一闪而过。

> 注意：不要双击 `app.py`。它不是独立程序，必须由 `streamlit run` 启动；
> 直接双击执行只会闪退或没有任何界面。

浏览器打开后，在左侧栏依次：

1. 加载检查标准（仓库不含内部模版，需**上传**你自己的归档范围表 `.docx`，或用 `checkpoints/附录C-基本建设.yaml` 这份示例）；
2. 选择资料类型（8 基本建设 / 9 设备仪器）、资料目录、责任单位、项目类型；
3. 按需勾选“读取 PDF 正文 + 识别红色印章”，可选深度模式与每份最多读几页；
4. 点“① 扫描目录”，再点“② 开始检查”；
5. 在“缺项清单 / 疑似待确认 / 印章核查”页签里逐条纠正；
6. 点“导出 Excel”并下载。

> 首次读取正文要 OCR，扫描件约 1–2 秒/页；结果按“文件 + 修改时间”缓存在
> `data/projects/<项目>-<哈希>/content_cache.json`，同一份资料再检查时几乎瞬时完成。
> 不想读正文就把勾去掉，退回纯文件名匹配。

`.doc` 文件需要本机安装 Microsoft Word（通过 `pywin32` 转换）或 LibreOffice（headless 转换）；
`.docx` 和 YAML 不依赖任何 Office 组件。

## 匹配规则

每个文件对每个候选检查点打分：

```
得分 = 20% × 分类编码 + 45% × 关键词覆盖率（IDF 加权） + 35% × 字符 3-gram 覆盖率
```

- **分类编码**：文件名/路径中的 3–4 位编码与检查点编码一致得满分，前缀一致得 0.6。
- **关键词**：从“主要项目文件”文字里抽取业务词（含“报告/报审表/合格证”等文书类型）；
  整词命中得满分，只命中词首片段按比例给分；**不按词尾匹配**，避免“砂使用跟踪记录表”
  因为尾部相同而命中钢筋资料。同义词换序（“光缆OPGW”↔“OPGW光缆”）在归一化后的路径上
  再算一次，取两者较高值；文书类型词按同一族（“评级记录”↔“质量验收记录”）计分，
  但只在主语基本对上（关键词前缀命中 ≥0.6）时才给，避免一张“开箱检查记录”顶替“验收记录”。
- **字符 3-gram**：兜底写法差异，例如“报审表”写成“报审资料”。

判定阈值：`≥ 0.62` 已匹配，`0.40–0.62` 疑似，`< 0.40` 缺失；可选项未提供时记为不适用。

为避免“看起来像就判已匹配”，另加了几道保险：

| 场景 | 处理 |
| --- | --- |
| 文件名带分类号但与检查点不一致 | 最高只到疑似 |
| 只命中“试验报告/报审表”等通用词，主语没出现 | 最高只到疑似 |
| 主语只出现在文件夹名里，文件名里没有 | 最高只到疑似（文件夹罗列的字样不能证明某份文件存在） |
| 要的文书类型（交底/报告/记录…）只在文件夹名里出现 | 最高只到疑似；同义文书类型（试验报告/检测报告、验收记录/验收表等）视为同一类 |
| 检查点是“见证取样记录”这类重复文字 | 必须命中归档内容里的区分词（水泥/砂/碎石…），否则降权 |
| 要“检测报告”却只有“检测方案/记录” | 得分 ×0.80 |
| 命中排除词（如“用水”） | 得分 ×0.15 |
| 同一文件支撑超过 3 条检查点 | 标注“注意合卷核对” |
| 清单与文件名只是语序不同，如“开工报审及开工报告”对“开工报告及报审” | 编码一致、每个分句的文书类型和主语都在文件名里出现时，补到 0.65（已匹配，中等置信度） |
| 清单与文件名换序/换词，如“基础分部工程开工”对文件名“分部工程开工报审表” | 长词必须由**文件名**支撑（首尾锚点 + 二字覆盖率 ≥40%）；文件夹名只能补“基础/土石方/接地”这类 2 字分部前缀，且文件名要完整含住其余至少 5 个字。全部长词满足补到 0.65，只满足一部分最高抬到疑似，不判已匹配 |
| 文件名与清单写法差别较大 | **按分类号找文件夹 → 在文件夹内做语义匹配**：目录名含检查点分类号（如 `AX-8233-1`）时，把清单拆成分句（括号里的限定说明先去掉，避免“隐蔽工程(基础)签证”拆出一个裸“基础”），逐句与文件夹内文件名比对（顺序覆盖 + 二字覆盖率，首尾二字必须命中）。**任一分句找到就算已匹配**，没单独找到的分句写进理由（“未单独找到：作业指导书报审…”）由人工复核；一个都没找全但有相近文件时抬到疑似并列出候选 |
| 清单一条里含多份文件、现场只归了一卷 | 例如清单写“立塔施工方案、作业指导书报审及附件、执行文件”，实际文件夹里只有高塔组立专项施工方案。**卷内目录标签**（文件夹名）同时写明主语和文书类型、且文件名也带该文书类型时，这一分句按“找到”处理 |
| 同一卷里有多个相近文件 | 证据文件按“清单原句原样出现在文件名里 > **文书类型覆盖度** > 主语首词是否出现 > 主语相近度 > 短文件名”排序。文书类型是文件的**主题内容**（施工方案 ≠ 开工报告），主语（架线分部）只是**分类**、同卷几份都沾得上，所以主题先于分类：清单要“架线分部工程施工方案报审表”时，只带“报审表”的“架线分部开工报告及报审表”压不过“导线架设专项施工方案及报审表”。主题相同的几份再用分类区分：“导线架设专项施工方案”优于“跨越施工专项施工方案”。主语变体按长度开方加权，避免“基础”这种两字变体命中整卷 |
| 同义词与文书类型差异，如“铁塔组立”对“杆塔分部”、“检测报告”对“试验报告” | 内置同义词表（铁塔/杆塔、桩基/桩基础、立塔/组立、架设/架线、消缺/缺陷、盘测/单盘测试、光缆OPGW/OPGW光缆等）与文书类型族（试验/检测、验收记录/验收表/评级记录/质量验收记录、报审、开工报告、合格证/证明、竣工图、记录/台账、清单/汇总表/明细表/统计表）；名称不同但语义一致时按同一份文件处理。同义词同时作用于关键词得分（原词、归一化两种写法取高），文书类型族只认 4 字以上的等价词，且主语要先对上 |
| 现场封皮写“分项工程质量验收记录”，清单写“检查及评级记录” | 同一张表的不同叫法。文书类型词按族计分，主语（展放/紧线/附件安装）仍要命中；一份“导地线展放”验收记录不会因此顶替“紧线”那条 |
| 清单写“OPGW光缆展放施工”，文件名写“复合光缆OPGW展放施工” | 光缆与 OPGW 语序相反，词首前缀只剩“OPGW”。同义词归一化后按“OPGW光缆展放施工”比对，主体词从 0.33 提到 0.83 |

阈值和权重是经验值，集中写在 `core/matcher.py` 顶部，便于按项目调整。

## 文件清单标准（`序号 | 文件名 | 立卷`）

有些项目手上没有《归档范围及保管期限表》，但有**竣工资料 PDF 文件清单**：按案卷顺序列出
本工程实际交的每一份文件。这种 docx 也能直接当检查标准用，`docx_parser.py` 会自动识别
（找不到“分类号 + 主要项目文件”的表时，改找“文件名 + 立卷 / 序号”的表）：

- **案卷标题行**（三列文字相同，Word 里是合并单元格）→ 一卷，从开头的 `AX-8230-1`
  取 3~4 位分类号；没有分类号的卷继承上一卷，并在解析诊断里提示。
- **每个数据行** → 一条检查点，`文件名` 当“主要项目文件”，`立卷` 当责任单位，序号原样保留。
- 上级类目按编码补齐：`8 基本建设 / 82 交流输电线路 / <案卷名>`，项目类型照常可自动识别。

**这类标准的核对方向不一样，必须说清楚**：它列的是“实际交了什么”，所以查出来的是

| 结果 | 含义 |
| --- | --- |
| 缺失 / 疑似 | 清单里有这一份，目录里找不到 |
| 未归类（说明列写“清单里没有”） | 目录里有这份文件，清单里没列 |
| 已匹配 | 清单与目录对上了 |

它**不会**告诉你“按归档范围还该有哪些文件”——那需要归档范围表。界面上加载这种模版时
会直接给出这条提示。

“清单里的这份目录里没有”按普通匹配判定即可；反方向（目录里多出来的）不能只靠分数阈值：
多出来的文件常常长得像清单里的某一份（0.5~0.6 分），所以清单模式下改成
“**没有被任何检查点当作证据用过**”即算清单外，但加两道闸防止误报——编码不在本次
资料类型/项目类型范围内的（如 9x 那部分）不算；最高分已到 0.62 的不算（证据每条只留前三份，
排第四的会被挤出去，它其实对得上清单）。

## 按内容批量改名

左上角页面切换里的 **文件批量改名**：点“📁 选择文件夹”弹系统对话框选目录 → 生成新名字 →
表格里预览/手改 → 确认改名。只改文件名，不动文件内容；每次改名写日志，改错了点
“撤销上一次改名”按批次倒着改回去。

选目录用的是 Windows 原生的对话框（`core/folder_picker.py`）：对话框放在**独立子进程**里跑，
因为 Streamlit 的脚本跑在工作线程里、Tk 在工作线程里容易卡死；子进程选完把路径写到 stdout
再取回来。机器上没有 Tk 或者对话框打不开时侧栏会把原因显示出来，并留了一个
“手动粘贴路径”的折叠框兜底。

**命名思路：能用文件自带的标题，就不用自己总结。** 红头文件的“关于……的通知”、
表格的“表B.0.19施工质量验收及评定项目划分报审表”，本身就是最准的文件名——重新总结
反而容易丢信息。所以流程是“取标题 → 删噪音 → 压长度”：

| 步骤 | 规则 |
| --- | --- |
| 取标题 | 先找带文种词（通知/报告/报审表/验收记录/交底/承诺书/作业指导书…）的那一行；标题被排版拆成几行就往后接，遇到“一、”“（1）”、字段行、冒号结尾就停；都没有时退回第一段像标题的内容 |
| 删系列抬头 | 成套发布的技术文件封面上有“发文单位 + 这套书的名字 + 第X部分”，对每份都一样、认不出是哪份：抬头行整行跳过，只从“第X部分：”后面开始取题目；“作业指导书/技术标准”这类文种从抬头补到题目末尾（`第1部分：输电线路外拉线悬浮抱杆分解组立铁塔` → `输电线路外拉线悬浮抱杆分解组立铁塔作业指导书`） |
| 认图纸 | 图面开头是注记（导线型号、桩号），当不了文件名；有“出图专用章”时改从图签里取图名，如 `平断面图4（2A1~3A23）` |
| 删噪音 | 表号（表B.0.19 / Q/CSG 表 1-4.2 / `Q/CSG表1-B.8` 只留 `B.8`）、档号标签（`【S005】`）、文号（运峰综〔2022〕7号）、单位名（…有限公司文件）、日期、编号/编码/工程编号行、纯英文行（封面上的 `CHINA SOUTHERN POWER GRID`） |
| 删工程名 | 优先取“工程名称：…”字段；没有字段就在正文里找**出现 ≥2 次**的“……工程”（红头文件标题和正文各写一遍）。开头的“成立/推进/完成”这类动词一并去掉 |
| 压长度 | 去掉开头的“关于”、结尾的“的”；超过 40 字时在顿号/逗号处截断，没有就硬截 |
| 合法化 | Windows 非法字符换 `-`，中文之间的 `/` 直接去掉（“报审/报验表”→“报审报验表”） |

读法沿用检查器那套：文字层优先，没有才 OCR；**一页里出现带文种词的标题就停止读取**，
不再翻后面的页。Word（.docx / .doc）直接解析段落和前两个表格，不走 OCR。

实测（`文件改名测试集`，15 份扫描件，原名是 `hvjgsd (1).pdf`、`higjhb (2).pdf` 这种）：

| --- | --- | --- | --- |

## 正文与印章规则

读取顺序决定成本，所以先便宜后贵：

1. **文字层优先**：电子版 PDF 直接 `get_text()`（毫秒级）；只有该页没有文字层才渲染成图跑 OCR。
2. **读到够用就停**：逐页累计正文，每读一页用候选检查点的关键词覆盖率算一次正文分，
   达到 0.80 或累计 6000 字就停止翻页。一次检查里同一文件只读一次，结果进缓存。
3. **只读值得读的**：默认只读“疑似”项的候选文件（文件名已有候选，正文用来确认）；
   深度模式才额外把“未归类文件”读一遍，用正文标题去救“缺失”项。

判定：

| 场景 | 处理 |
| --- | --- |
| 正文分 ≥ 0.55，且清单要求的文书类型在正文里出现 | 疑似 → **已匹配**，理由写“正文命中：水泥出厂合格证…” |
| 多条检查点文字相同、只有归档内容不同（水泥/砂/碎石/钢筋…的“见证取样记录”） | 正文或文件名必须命中**自己那一条的区分词**（如“07钢筋”），否则不升级——否则一份商品混凝土取样记录会把钢筋、钢筋焊接几条一起升上去 |
| 正文分 < 0.12 但文件名匹配上了 | 不改状态，只在理由里追加“正文未见清单字样，建议复核”；但摘掉文书类型词后**主语仍能在正文里找到**（同义词、换序写法，如“杆塔分部工程开工”对正文“铁塔组立分部工程开工报告”）时不提示 |
| 第 1 候选文件没读到正文 | 不下正文结论、也不提示复核（拿第 2 候选的低分去说主证据对不上没有意义） |
| 深度模式：未归类文件正文分 ≥ 0.70 且领先第二名 ≥ 0.10 | 缺失 → **疑似**（不直接判已匹配，正文常会顺带提到别的文种） |
| 正文分落在两者之间 | 保持原判，人工在“疑似待确认”里复核 |

印章识别（`core/seal.py`）只看红色油墨：HSV 红色掩膜 → 膨胀把“圆环 + 环内文字”粘成一体 →
按尺寸、长宽比、红色密度、**直边（表格框）**、**四角是否填满（矩形框 vs 圆章）** 五道筛。
结论分三档：`有`（检出）、`未检出`（彩色页面上确实没有）、`不可判`（整页彩色像素 < 0.4%，即黑白扫描件）。

正文分阈值、停止阈值写在 `core/content.py` 顶部。

## YAML 检查清单格式

推荐直接上传 docx 自动解析。需要手写或程序生成时，使用 canonical 格式：

```yaml
schema_version: 2
meta:
  name: 我的检查清单
checkpoints:
  - id: CP-8232-0001
    code: "8232"
    path: [基本建设, 交流输电线路, 项目施工, 基础工程]
    category: 基础工程
    archive_content: 01基础工程
    text: 施工组织设计报审及附件、交底
    filing: 施工/监理          # 对应“立卷”列，多个单位用 / 分隔
    retention: {建设: 永久, 施工: 30年}
    keywords: [施工组织设计]    # 可选，补充匹配词
    optional: false
    match:
      filename_exclude: [用水]  # 可选，命中即大幅降权
```

`nodes` 可省略：加载时会按 `path` 自动合成类目层级，供项目类型下拉使用。
旧版 `groups/items` 格式仍可读取，加载时会提示已转换。

在界面“标准预览”页签里可以把当前模版导出为上述 canonical YAML，作为二次编辑的起点。

### 跨项目留出（评测 7）

在 A 项目用 5 折算阈值，原样套到 B 项目，B 项目不参与调参：

| 方向 | 阈值来源 | 阈值 | P | R | F1 |
| --- | --- | --- | --- | --- | --- |
| 项目A→项目B | 项目A 5 折中位 | 0.40 | 73.6% | 53.2% | **61.8%** |
| 项目A→项目B | 项目B自身 5 折中位（对照） | 0.42 | 76.7% | 52.4% | 62.3% |
| 项目B→项目A | 项目B 5 折中位 | 0.42 | 89.9% | 58.9% | **71.2%** |
| 项目B→项目A | 项目A自身 5 折中位（对照） | 0.40 | 90.6% | 63.6% | 74.7% |

“对照”行用了目标项目自己的 5 折中位，借用了目标项目标注信息，数值略偏乐观；跨项目行只用源项目阈值，目标项目完全没参与调参。

结论：**阈值可迁移**（跨项目比“目标项目自身 5 折中位套全量”的对照只低 0.5 和 3.5 个 F1 点），**但分数校准会变**
（同样 0.40，项目A P=90.6%，项目B只有 73.6%）。换项目可以先沿用阈值，但不能沿用准确率预期，
应在目标项目重标 30–60 条校准。汇总见 `评测/跨项目结果.csv`。

### 三句实话

- **什么时候会错**：同一分类号文件夹里，「报审表 / 方案 / 交底记录」会压过「验收记录 / 验收评级」；
  竣工图文件名里的图号（`[S21201S-D0301-01C]`）会把 3-gram 稀释到 0.05 左右。
  项目B 4 条严格错误（3 误配 + 1 空判成有）全部是这类“同卷同分类号、文种不符被兜底抬到 0.65”。
- **有多少停在疑似**：项目A 53 条、项目B 44 条需要人工看；项目A 43 条对（81.1%），项目B 24 条对（54.5%）。
  复核完，召回从严格模式的 35.1% / 34.1% 提到 63.6% / 53.2%。
- **换项目还能不能用**：两个项目互测过，阈值可迁移（F1 只掉 0.5–3.5 个点），但准确率预期不能照搬
  （同样 0.40，项目A P=90.6%，项目B 73.6%）。换项目应重标 30–60 条校准分数线。

口径与局限：两个项目各有约 100–125 条「没有归档」，其中可能混有“文件存在但没进候选池”

复现：`python 评测/评测4_评测.py`（项目A）、`python 评测/评测7_跨项目.py`（跨项目）；

## 已知限制

- **文件名仍是主证据**。文件夹名用于按分类号定位候选目录、补“基础/土石方/接地”
  这类分部前缀；卷内目录式命名（“塔组立开工报告、高塔组立方案……”）可以证明**同卷里有这类
  文件**：主语和文书类型都在文件夹名里、且文件夹内确实有一份带该文书类型的文件时，清单里
  对应的分句算“找到”。但文件夹名不能凭空指认某一份文件——没有文书类型可核对的分句
  （“项目部成立”）仍要求整句出现在文件名里，否则最高只到疑似。语义匹配仍可能误判，
  证据文件也可能选到同卷里相近但不是主件的那份，最终需要人工复核“疑似清单”和证据列。
- **正文只读前几页**。默认每份最多 3 页，正文分达到 0.80 即停止翻页；如果标题页之后才出现
  关键字（例如目录在前、正文在后），可能读不到。扫描件 OCR 对印刷体效果尚可，
  手写、盖章遮挡、倾斜扫描的识别质量会明显下降。
- **深度模式更慢**。它会读未归类文件的正文，一次检查可能是标准模式的 1.5–2 倍耗时；
  救回来的条目只判“疑似”，必须开卷确认。
- **印章识别只认红色**。黑白扫描件、复印件的红章会判为“不可判”，不当作“没盖章”；
  红头文件、红色表格框、彩色照片靠尺寸/直边/四角规则排除，但版式非常规的文件仍可能误检。
- **整类缺失是启发式判断**：三级分类下全部缺失且条目数 ≥3 时提示“整类缺失”，
  叶子类目全部缺失且 ≥2 条时提示类目级缺口，不排除检查点本身写得过细。
- **一次只查一套编码**。`8 基本建设`（80–89）与 `9 设备仪器`（90–99）是两套分类，
  设备仪器类材料（塔材、导地线、金具、绝缘子的合格证与厂家文件）归 9x，立卷单位是
  “建设/物资供应”而不是“施工”。扫描后如发现另一套编码，侧栏会提示文件数并可一键切换
  （同时把责任单位改到有检查点的那个）。
- **文件清单标准只能查“清单与目录是否一致”**。它列的是实际交了什么，所以查不出
  “按归档范围还该有哪些文件”；反方向的“清单外文件”靠“没被任何检查点当证据用过”判定，
  对得上清单但被前三名挤掉的、或对某条也到了 0.62 的多余文件不会报出来。
- **项目类型必选**（可自动识别）。识别依据是目录/文件名中的 3–4 位编码；
  目录命名不规范时会识别失败，需要手动选择。切换模版或示例目录时选择会自动重置为
  “自动识别”；扫描后若目录编码与手选类型不一致，侧栏会给出警告，避免整批检查点筛错。
- **人工纠正按项目目录落盘**（`data/projects/<项目名>-<路径哈希>/overrides.json`）。
  移动资料目录会被视为新项目，纠正记录不会自动跟随。
- `.doc` 转换依赖 Word 或 LibreOffice；两者都没有时会给出明确错误，不会静默失败。
- 超长 Windows 路径使用 `\\?\` 前缀回退，极少数网络盘/权限受限目录仍可能读取失败。
